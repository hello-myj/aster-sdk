# Aster SDK 使用说明

直接开发普通应用可从 `aster init` 开始；已有安装包先用 `aster verify` 查看目标架构、最低 ABI 和板型限制，确认后再串口部署。[清单字段与启动检查](app-development.md) · [串口安装](serial-console-transfer.md)

本页适用于 SDK 4.5.0。可选 `--hardware`、`supported_boards` 和自动识别架构的 `aster verify` 均可直接使用。开发板首次开机也可复制[离线 SD 卡资源](https://github.com/hello-myj/aster-firmware/blob/firmware-v4.5.0/docs/offline-sd.zh-CN.md)。

开发包包含 APP 编译器、命令行工具、示例、手册和开发 Skill。应用按 CPU 架构构建。Windows 包自带 Python，Linux 包需要 Python 3.12。

## 安装

Windows 运行 `aster.exe install`；Linux 运行 `./aster install`，然后按命令输出加载环境。使用 `aster doctor` 检查工具，`aster targets` 查看 CPU 目标。

## 配套固件

```text
aster firmware list
aster firmware download --board osptek-p4-st7102
aster firmware flash --board osptek-p4-st7102 --port COM11
aster firmware flash --board lckfb-s3 --port COM12
aster firmware download --board fakepod-s31 --output images
```

下载内容固定到固件 Release，并在烧录前校验 SHA256。烧录使用整合镜像，从地址 0x0 写入，包含对应启动与分区数据。设备必须插入 SD 卡。可先复制固件 Release 提供的离线字体与商城，再插卡开机；空卡也可按屏幕提示联网初始化。升级前保留需要的数据。

## 创建、编译和安装 APP

```text
aster init my-app --template hello --id com.example.hello --target riscv
aster build my-app
aster deploy my-app/dist/riscv/com.example.hello.ast --target riscv --port COM11 --run
```

创建时选择的架构保存在 `app.toml` 的 `[sdk].target`。鱼鹰光电 P4C5 和 FAKE POD NANO PRO 使用 `riscv`，立创 ESP32-S3 实战派使用 `xtensa`。同一工程可以执行 `aster build my-app --target xtensa`，为另一架构单独生成 AOT 包。安装前返回设备桌面，并关闭独立串口监视器。设备屏幕显示文件接收、校验、安装和结果。需要的资源通过 `app.toml` 的 `assets` 声明打包。

## 桌面调试

```text
aster sim --profile osptek-p4 --app my-app
aster sim --profile lckfb --app my-app
aster sim --profile osptek-p4 --app my-app --resources path/to/resources
```

首次运行下载并校验独立桌面模拟器，之后使用本地缓存。当前桌面二进制适用于 Windows x64；其他平台可使用模拟器源码。已编译工程按配置读取 dist/riscv 或 dist/xtensa，并自动查找包旁的 resources 目录。可直接指定 --app 包路径。调试模式使用本地字库；支持自定义分辨率、PNG 截图和带系统音效、游戏音效及背景音乐的 MP4 录屏。

模拟器执行安装包中的 WASM，不代表实机 AOT 的帧率和内存表现。完整 API 与工程配置见 [APP 开发手册](app-development.md)。


## 可选的板型简称

`aster build my-app --target riscv` 可以为鱼鹰光电 P4C5、FAKE POD NANO PRO 及使用相同 AOT 配置的新板生成一份包。开发新板只需选择现有 CPU 架构，应用工程和 SDK 均无需登记板名。

已有脚本也可以继续用 `aster build my-app --hardware osptek-p4`。SDK 内置的板名简称会选择对应架构，并将包单独存到 `dist/riscv/osptek-p4/<应用ID>.ast`。包内 `target_id` 仍为 `riscv`。默认构建和串口安装都可以只使用架构。

在 `[app]` 的 `requires` 中填写缺少就无法运行的功能，例如系统播放器依赖 `media-player`。固件在打开 APP 前核对本机能提供的能力；缺少必需能力时拒绝启动。可降级功能写入 `optional`，由 APP 使用 `aster_system_has_feature` 查询。用 `aster_display_get_info` 获取实际布局尺寸。商城的上架范围可由发布配置独立指定。

用 `aster verify 文件.ast` 可以离线查看安装包的架构、`supported_boards` 和 `requires`。例如专用播放器可在 `[app]` 写入：

```toml
supported_boards = ["fakepod-s31"]
requires = ["display", "touch", "media-player"]
```

新版固件在每次启动前按自身 `board` 标识和实际能力放行。旧包缺少 `supported_boards` 时继续按架构和能力运行；引入此字段之前的固件会忽略板型限制。
